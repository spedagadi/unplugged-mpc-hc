on both the H.264 SMPTE bars clip and a real user file (`Exodus.mp4`). Focus
moves to S3 (UI shell) and S4 (DeckLink capture) against this seam.

## 3. Decided design (locked)

- **Form factor B** — unified one-window UI (video + left LIVE pane + right rail + bottom bar), drawn in/around mpc-hc's own frame, not a parallel shell.
- **Engine = mpc-hc in place** — no clean-room DShow engine; the frame→renderer machinery and renderer-setup protocol already live in mpc-hc (`FGManager` FCGFilter renderer branch, `mvrInterfaces.h` madVR protocol). S2 lifts the minimum surface (renderer plumbing + `IExFilterConfig` flags for MPCVR) without pulling `FGManager`.
- **Capture source = reuse** — `C:\Code\videoprocessor\src\VideoProcessor-Lib\microsoft_directshow\live_source_filter` (`CLiveSource`, push-source, latency/PPM/queue metrics) instead of writing a source filter from scratch. ❓ open: link-vs-lift (§6).
- **Signal monitor** — port `decklink_monitor.dll` (read-only `IDeckLinkStatus`), host-owned.
- **Webserver** — prototype/companion/protocol seed; not the control spine.
- **Scope v1** — VP ingest + Media local files; DVD/BD main-feature via LAV; **no** recording, network surfaces, or disc menus (deferred, API-reserved).
- **Toolchain post** — build recipes baked into memory; environment quirks documented (NoDefaultCurrentDirectoryInExePath, batch encoding, winsdk pin, ucrt64 layout).

## 4. S1/S2 resolution — what was wrong, how it was fixed

### 4.1 The visible-video blocker

The standalone S1 spike (`tools/engine_spike/s1_windowed.cpp`) built a valid
graph (`source → LAV Splitter → LAV Video → MPCVR`), connected all pins,
hosted MPCVR via `IVideoWindow::put_Owner`, ran the clock, and showed a black
window. All machine-side checks (filter list, CLSID/module identity, position,
`EC_COMPLETE`) passed — but no frames appeared. Iterating on the test clip
(MPEG-4 → H.264) and window ownership order did not change the outcome.

### 4.2 What was actually wrong

Two independent things, one architectural:

1. **The old test clip was a red herring** — `tools/engine_spike/test30.mp4`
   (mpeg4 testsrc) decoded to white/black in known-good mpc-hc too. It was
   replaced with `tools/engine_spike/test30_h264.mp4` (H.264 SMPTE bars). The
   H.264 clip renders correctly in normal `mpc-hc64.exe` (user-verified).
2. **The standalone spike was the wrong scope for a visible-video proof.**
   MPC-HC drives MPCVR through `CFGFilterVideoRenderer::Create` →
   `CreateAP9(CLSID_MPCVRAllocatorPresenter, hwnd, ...)` →
   `CMPCVRAllocatorPresenter::CreateRenderer` → `CoCreateInstance(CLSID_MPCVR,
   GetOwner())` (**COM-aggregated** into the presenter) → set
   `ISubRender`/`ISubRender11` callbacks → set `IExFilterConfig` flags
   (`lessRedraws`, `d3dFullscreenControl`) → then `put_Owner(hwnd)` on the
   wrapper. `CLSID_MPCVRAllocatorPresenter` is **not a registered COM class**
   — it lives in-process inside mpc-hc. The spike's `CoCreateInstance(CLSID_
   MPCVRAllocatorPresenter)` therefore failed with `0x80040154` and it fell
   back to plain `CLSID_MPCVR` — a legal path, but missing the flag/aggregation
   setup that the standalone MPCVR filter needs to actually present.

### 4.3 How it was resolved

Instead of retro-fitting the standalone spike, we implemented the actual
architecture goal (§5.5 of `Ingest-Architecture.md`): the engine seam. The
render binding lives inside the engine, not the demo host.

- New static library **`src/mpchc_engine/`** (`mpchc_engine.vcxproj`,
  registered under the `Libraries` folder in `mpc-hc.sln`), builds clean
  Release/x64 via the repo props with `MPCHC_WINSDK_VER=10.0.26100.0`.
- Class **`MpcPlayer`** ([MpcPlayer.h](../src/mpchc_engine/MpcPlayer.h),
  [MpcPlayer.cpp](../src/mpchc_engine/MpcPlayer.cpp)):
  - Commands: `Open`, `Play`, `Pause`, `Stop`, `Seek`, `ResizeVideo`.
  - Properties: `GetSnapshot`, `SnapshotJson` (state / position / duration / source).
  - Events: `SetEventCallback(fn(name, snapshot))` — `opening / opened / state / time / error`.
  - Renderer-agnostic: `Renderer::Auto | VMR9 | EVR | MPCVR` (falls back within the enum on `CoCreate` failure).
  - **Render binding**: `AttachRenderTarget(HWND)` + `ConfigureRendererWindow()`:
    `IMFVideoDisplayControl::SetVideoWindow` + `IVideoWindow::put_Owner /
    put_WindowStyle / put_MessageDrain` + `IExFilterConfig::Flt_SetBool(
    "lessRedraws"/"d3dFullscreenControl", true)`. `ResizeVideo()` calls
    `IMFVideoDisplayControl::SetVideoPosition` + `IBasicVideo::
    SetDefaultSourcePosition/SetDestinationPosition` +
    `IVideoWindow::SetWindowPosition`.
- Visible acceptance driver **`tools/engine_s2/s2_driver.cpp`** +
  **`build_s2_driver.bat`**: creates a `WS_OVERLAPPEDWINDOW` host, black
  background, `WM_SIZE → player.ResizeVideo()`, blocking `GetMessage` loop
  with `WM_TIMER` auto-stop (no `Sleep`/no wait-cursor), CLI:
  `s2_driver.exe [--renderer auto|vmr9|evr|mpcvr] <media-file>`.

### 4.4 Verified end-to-end (user-visible)

- `s2_driver.exe --renderer mpcvr .\test30_h264.mp4` → **SMPTE bars visible**;
  transport, snapshot, events all correct; clean stop.
- `s2_driver.exe --renderer mpcvr D:\Jdownloader\Exodus.mp4` → **real content
  plays correctly** through MPCVR-Zion; mouse-over on the video surface is
  smooth after switching the loop to blocking `GetMessage`.

### 4.5 What is intentionally *not* in S2 yet

- Full MPCVR allocator-presenter path (subtitles/OSD via `ISubRender`
  callbacks, aggregation into `CMPCVRAllocatorPresenter`). Basic video
  presentation works without it; adding it requires linking / lifting
  `SubPic` + `VideoRenderers` scaffolding. Deferred; no current blocker.
- Playback-to-EOF and `--duration` in the driver — driver still stops on a
  15s timer for now (test harness).
- Property-observe polling thread (periodic `time` event) — API stub in
  place, no polling loop yet.
